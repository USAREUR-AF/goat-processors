## Large generated scenario

Input, written by the harness (`tools/perf/scenario.py`, seeded, deterministic): 12 objects for 600 s; sensors radar (4 s), beacon (1 s), beacon2 (1 s, clock +200 ms), passive (2 s, clock drift 10 ms/min); 18571 reports and 600 ticks; seed 20261120. The same reports go to every function; fuse's also carry `fuse.group` (the truth object). Packs: `correlate-gnn-imm`, `correlate-assign-time` (correlate), `filter-thin` (filter), `fuse-independent` (fuse), `quality-time` (quality).

Through the vector commands: the harness writes the scenario as a vector of each pack, with the expected events, trace and snapshot from the Python engine, into a copy of the tree that holds no other scenario vectors, builds every engine there and times the same commands. So each number also covers parsing that vector and comparing every step; vector file sizes: `correlate-assign-time` 138 MB, `correlate-gnn-imm` 21 MB, `filter-thin` 29 MB, `fuse-independent` 14 MB, `quality-time` 47 MB. A cell that fails is an engine that cannot run the large scenario today through its vector command, or whose output differs from the Python engine's on it; the common runner of the refactor will measure it.

### Engine calls only (runner contract)

An engine's contract runner (README.md, "Runner contract") times its engine calls only: every `ingest` and `tick`, and `snapshot()`, not reading or parsing the input. Reports per second here = reports / run time; peak memory is the whole runner process. Its events and trace are checked against the Python engine's on the same input. Today only Python has a runner (`tools/perf/run_python.py`); the six others get theirs in the refactor (their IO module), and the harness then fills their rows with no change.

## What each number covers

| Engine | Vector command timed |
|---|---|
| python | `python3 -m unittest <function test module>` (CPython, no build): interpreter start, JSON parse of every vector file, the engine, comparison with the expected events, trace and snapshot |
| rust | the function's test binary from `cargo test --release --no-run`, run with `--test-threads=1`: JSON parse, engine, comparison; its scenario, load and shipped-pack tests |
| go | the package's test binary from `go test -c`, run in the package directory: JSON parse, engine, comparison; every test of that package (unit tests included) |
| java | `java -cp build <VectorTest class> <root>` after `javac --release 17`: JVM start and JIT warm-up, JSON parse, engine, comparison |
| cpp | the function's runner from `cmake --build` (CMAKE_BUILD_TYPE Release, the project default), run with the root: JSON parse, engine, comparison |
| erlang | `erl -noshell -run <module> main <root>` after `erlc`: VM start, JSON parse, engine, comparison |
| zig | the function's test file compiled by `zig test -O ReleaseFast --test-no-exec` with the same `paths` module build.zig makes, then run: JSON parse, engine, comparison |
